# Technical Case Study Template

Use this template for every portfolio project so recruiters and hiring managers can scan business impact, technical depth, and your ownership quickly.

## 1) Snapshot

- Project Name:
- Role:
- Period:
- Category (Product / Platform / Client):
- One-line Value Pitch:

## 2) Context

Describe the product/business setting, target users, and why the project mattered.

Prompt:

- Who was this for?
- What business or user problem was urgent?
- What constraints shaped the work (time, budget, compliance, device/network)?

## 3) The Challenge

Describe the hardest engineering or product-delivery challenge.

Prompt:

- What made this non-trivial?
- What could fail if not handled well?

## 4) My Solution

Explain exactly what you led and shipped.

Prompt:

- What architecture, UX, or implementation decisions did you make?
- What tradeoffs did you choose and why?
- What did you own directly vs support as part of the team?

## 5) Key Results

Add measurable outcomes whenever possible.

Prompt:

- Conversion, retention, latency, uptime, cost, quality, operational speed.
- Before/after metrics are ideal.

## 6) Hard Problems Solved

List technically difficult aspects.

Prompt:

- Security/privacy concerns
- Data integrity and synchronization
- Scalability/performance constraints
- Reliability in real-world network/device conditions

## 7) Tech Stack

List core technologies and integrations used.

## 8) Interview Talking Points

Write 3–5 concise bullets you can confidently explain in interviews.

Prompt:

- One architecture decision
- One debugging/performance story
- One product-impact story tied to metrics

## 9) What I'd Do Next

List improvements you'd ship next to show product thinking and seniority.

Prompt:

- Monitoring/observability gaps
- Experiments and growth loops
- Reliability or developer-experience upgrades

## 10) Proof Assets

Attach links that prove quality and outcomes.

Checklist:

- Live demo
- Code repository
- Screenshots (desktop/mobile)
- Flow diagram
- API sample (if relevant)
- Stakeholder testimonial (optional)

---

## How this maps to your codebase

In `lib/portfolio-data.ts`, each project should have:

- `context`
- `summary`
- `challenge`
- `solution`
- `impactMetrics`
- `hardProblems`
- `interviewTalkingPoints`
- `nextSteps`
- `techStack`
- `links`

This keeps your UI and documentation aligned and makes updates quick.
